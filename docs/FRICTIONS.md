# Frictions — what real usage hits, and what became of each

Phase 13's practice ([PLAN.md](PLAN.md)): every friction that real usage
hits becomes either a **fix** or a **named refusal with a reason** — never
a shrug, never silence. The list is the deliverable; an empty disposition
column is the only failure state.

Lessons arriving from the author's proprietary applications appear here in
neutral wording, per the naming rule in PLAN.md's change log. Lessons from
[Comptoir](../examples/comptoir) and public users appear as themselves.

| # | Friction, as hit | Disposition | Where |
|---|---|---|---|
| 11 | The panel guessed a deployment's port by scanning its source, so it showed 8110 for an application deployed on 8250 — and starting it from the panel would have bound the wrong port AND written the database beside the code, where the next redeploy deletes it. | **Fixed** — the panel reads `.ringserv/deployment.yaml` first and starts a deployment with its own `--port` and `--data`. Gated: a panel that can quietly lose the record is worse than no panel. | `panel.zig` |
| 10 | `statFile` answers `error.IsDir` for a directory on Windows, so the obvious way to ask "file or folder?" — stat it, read `.kind` — never gets a kind at all, and `ringserv deploy <folder>` refused the most ordinary thing anyone would deploy. | **Fixed** — asked by OPENING it as a directory. | `deploy.zig` |
| 9 | The panel's app row overflowed horizontally on a narrow window, pushing the application's NAME off the side — the one thing the row exists to tell you — and giving the page a horizontal scrollbar. Seen at 620px, where "comptoir" read as "ir". | **Fixed** — the row wraps, and below 720px the buttons take a line of their own rather than squeezing the identity off it. | `panel.html` |
| 8 | Standing up one deployment took five hand-written PowerShell scripts, and **every one of them was a thing the server should do itself**. Worse, changing a line of code meant stopping the server, so a running application could not be corrected without an outage — however small. | **Fixed, half of it** — `ringserv reload` and a panel **Reload** button change a live server's code with no restart, no rebind and no dropped connection (62 ms, 17 gates). `deploy`/`redeploy` are **not** built yet and [DEPLOY.md](DEPLOY.md) documents the manual path honestly rather than pretending a verb exists. | `serve.zig`, `panel.zig`, [PLAN.md](PLAN.md) phase 20 |
| 7 | `ringserv journal export` produces a file `ringserv journal import` refuses: "line 1 carries no hash". A native (64-hex) record's stored `body` carries no `prev` and no `hash` at all — those are separate DB columns, kept out of the bytes JournalAppend hashed — so a native row's exported line had nothing for the importer to check. | **Fixed** — export now INJECTS `prev`/`hash` into a native line's text before it goes out (`RsJournalInject`), and the check that reads it back strips that injection and retries (`RsJournalStripInjected`) rather than treating the line as a second dialect. On a row read straight from this worker's own table the strip finds nothing, so the retry costs one failed scan on the hot path and changes no verdict. The 16-hex legacy path is untouched — it already stored and verified the full line, correctly, since phase 13. Gated on the exact case the friction named as missing: an export→import round trip, for a purely native journal and for a mixed legacy→native chain, both proven byte-identical on re-export and both still refusing a tampered line at its exact position. 17 new gates. **Now the restorable backup is the journal export itself, not only the database file copy** — the ops drill in [DEPLOY.md](DEPLOY.md) still rehearses the file copy because it needed no code change to be trustworthy the day it was written. | `RsJournalInject`, `RsJournalStripInjected`, `JournalExport`, `JournalImport` |
| 6 | A JSONL export written by the ordinary Windows tool (`Set-Content -Encoding utf8`) begins with a UTF-8 BOM, and the importer answered "line 1 is not JSON" — sending the reader to inspect JSON that was perfectly correct. | **Fixed** — a leading BOM is stripped once, from the file rather than per line: a BOM belongs to a file, and a second one further in really would be corruption. | `JournalImport` |
| 5 | **No .NET client could POST to RingServ on Windows.** PowerShell and every .NET Framework app send `Expect: 100-continue` by default; the connection was dropped with no reply. httpz answers `100 Continue` by writing straight to the socket with `posix.write`, which on Windows is `WriteFile` — and WriteFile does not work on an overlapped socket. **The same one call is why SSE response streaming failed on Windows**, named as a platform gap in phase 18. Two symptoms, one syscall. | **Fixed** — vendor patch: `send()` on Windows, `write()` elsewhere. **Phase 18's Windows gap is closed with it**: `tests/stream-gates.js` now runs 21/21 on Windows instead of skipping. | `vendor/httpz/src/worker.zig`, [VENDOR_PATCHES.md](VENDOR_PATCHES.md) |
| 4 | A deployment could not move the port without editing the application it deployed. `--port` worked on `serve` and `panel` but not on `run`, and the yaml cannot do it either because the declaration beats the file by design. The concrete bite: Comptoir declares 8110, which is also the port its own test suite binds, so a counter and a test run on one machine would have killed each other. | **Fixed** — `--port` on `run` too, and the override is *printed* at boot, per the same rule the config file follows. | `main.zig` |
| 1 | A journal born under the older field discipline (16-hex truncated chains) could not move into a `Journal()` without breaking its own verification. | **Fixed** — `ringserv journal import` accepts the interchange dialect, verifies before writing, stores the original bytes, and native appends continue the imported chain. | `journal.ring`, 9 gates |
| 2 | A Latin-1 byte in a request body reached the journal — where nothing may be deleted — and permanently broke strict JSON consumers of that record. | **Fixed** — the HTTP door refuses non-UTF-8 bodies as 400, naming RFC 8259. | `serve.zig`, gate replays the byte |
| 3 | Re-hashing imported legacy records to the native 64-char discipline was considered and declined. | **Named refusal** — an inalterable record's chain is honoured, not upgraded: re-hashing would break the very chain the import exists to preserve. | `RsJournalCheckOne` |
