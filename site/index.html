From a function to a service, in ninety seconds

  1. Write functions.Ordinary ones. Nothing to import, nothing to register, nothing to configure first.
  2. Serve them.Run ringserv serve calc.ring. Every function in the file is now callable over the web.
  3. Call them.The values you send are matched to the function's parameters by their names, and whatever the function returns comes back as the answer.

Worried about what you just published? Run ringserv serve --explain calc.ring and it prints exactly which functions became callable, and how — then exits without starting anything. You never have to guess.

# calc.ring — the whole file

func add a, b
	return a + b

$ ringserv serve calc.ring

$ curl -X POST localhost:8080/api/v1 \
    -d '{"service":"calc","action":"add",
         "payload":{"a":19,"b":23}}'

{"code":0,"message":"OK","data":42}

When you need more than a few functions

RingServ([
    :port     = 8110,
    :database = "comptoir.db",

    :data = [ :menu = [ :name = :text, :price = :number ] ],

    :services = [
        :menu    = [ :table = "menu" ],        # list/add/edit/delete, from one line
        :orders  = new OrdersService,        # or write it as a class, if you prefer
        :receipt = [ :js = "services/receipt.js" ],  # this one is written in JavaScript
        :journal = RsJournalService("ventes")  # the sales record: readable, never editable
    ],

    :routes = [ [ :static, "/", "public/" ] ]
])

Contract(:orders, [                         # checked before your code runs
    :place = [ :in = [ :client = [ :type = :string, :required = true ] ] ]
])

Topology([                                 # which machine runs what
    :services = [ :menu = [ :site = :local, :authority = :server ] ]
])

Want a service to run in the browser instead of on the server, or both? Change one word in Topology(). Your application code does not change at all.

What is inside the file you download

AreaWhat you get
your codeWrite a service as a simple list, as a class, or in JavaScript — or write no service at all and let ringserv serve publish a file of ordinary functions.
your dataA real SQL database (SQLite) is built in — no server to set up, no driver to install. You describe your tables, write ordinary SQL, and say what each request must contain; bad requests are turned away before your code sees them.
historyA record you can only add to, never change. Each entry is sealed with a fingerprint of the one before it, so if anyone edits the past, the server points at exactly where. For accounts, audits, and anything the law says you must keep intact.
works offlineYour page can keep working without a network and catch up when it returns. Changes are sent once and only once, even if the connection drops mid-send.
javascriptA JavaScript engine is inside the binary, so a service can be a .js file. It follows the same rules as a Ring one and can call your Ring services by name — two languages, one application.
before you runringserv check catches mistakes without starting anything, and ringserv docs writes your API reference from the code you already wrote.
running itA small admin page in your browser to start, stop and watch your applications. Settings live in a plain ringserv.yaml. And journal verify reports a tampered record with a failure code, so you can run it nightly and be told rather than having to look.

How we know it works

625 tests, about a minute

The whole suite runs in roughly seventy seconds, so it runs often. A longer version adds stress tests and performance measurements.

Compared against real Ring

Around a thousand Ring programs are run twice — once by RingServ, once by the official ring — and the output is compared character by character. If RingServ ever disagreed with Ring, we would know that day.

Tested on all three systems

Every change is built and tested on Linux, macOS and Windows. The first time we did this it uncovered five bugs that a single computer simply could not reveal.

The documentation is tested too

The examples on our pages are pulled out of the pages themselves and actually run. If a guide stops being true, the build fails — so the instructions you read are the instructions that work.

Three things to know before you build on it

For HTTPS, put a proxy in front

RingServ speaks plain HTTP. It does not do HTTPS itself, on purpose: encryption libraries are large and change often, and copying one into this project would break the promise that the binary has no dependencies.

What to do: run Caddy, nginx or Traefik in front — a few lines of config, and they handle certificates for you. RingServ will refuse to start on a public address until you confirm you have done this, so you cannot publish traffic in the clear by accident.

Number formatting and config files cover the common cases

Two features are deliberately partial. Intl (formatting prices and numbers in JavaScript) supports eight languages and nine currencies. ringserv.yaml reads ordinary settings, not the whole YAML standard.

Why: full support would add more to the download than everything else combined. What to do: nothing, usually — and if you do step outside, you get a clear error telling you exactly what is missing. It never guesses and gets it silently wrong.

0.9 means "ready to use, not finished"

Everything described here works and is tested. But this is not 1.0 yet, so a command or a declaration may still change before then.

What to do: build with it, and expect to read the release notes when you upgrade. Anything the tests do not yet cover well is written down openly in the repository — we would rather tell you than have you find out.
