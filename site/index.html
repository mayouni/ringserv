From a function to a service, in ninety seconds

  1. Write functions.No framework, no declarations, no ceremony. A file is enough.
  2. Serve them.ringserv serve calc.ring — every top-level function becomes an action.
  3. Call them.Payload keys map to parameters by name; the return value comes back enveloped.

Not sure what got exposed? ringserv serve --explain calc.ring prints the exact mapping and exits. The tool states it, so you never have to trust it.

# calc.ring — the whole file

func add a, b
	return a + b

$ ringserv serve calc.ring

$ curl -X POST localhost:8080/api/v1 \
    -d '{"service":"calc","action":"add",
         "payload":{"a":19,"b":23}}'

{"code":0,"message":"OK","data":42}

When you need more than a function

RingServ([
    :port     = 8110,
    :database = "comptoir.db",

    :data = [ :menu = [ :name = :text, :price = :number ] ],

    :services = [
        :menu    = [ :table = "menu" ],        # five actions from one line
        :orders  = new OrdersService,        # a class; Action methods are public
        :receipt = [ :js = "services/receipt.js" ],  # JavaScript, same envelope
        :journal = RsJournalService("ventes")  # read-only by construction
    ],

    :routes = [ [ :static, "/", "public/" ] ]
])

Contract(:orders, [                         # validated at the door, not inside
    :place = [ :in = [ :client = [ :type = :string, :required = true ] ] ]
])

Topology([                                 # where each service runs
    :services = [ :menu = [ :site = :local, :authority = :server ] ]
])

Move a service between the page and the server by editing one word in Topology() — not the application.

What is in the binary

AreaWhat you get
servicesDeclarative, class, generic-table, JavaScript — and none at all: ringserv serve hosts a file of plain functions.
dataEmbedded SQLite with WAL, one connection per worker, plain SQL, and typed contracts enforced before an action ever runs.
historyJournal() — append-only, SHA-256 hash-chained, replayed to state, and never compacted. For records that must stay whole.
local-firstA trigger-maintained shape log, an exactly-once mutation queue, and compaction that tells a stale client to refetch.
javascriptA vendored QuickJS-ng with a WinterTC-shaped surface. A .js service gets the same envelope, contracts and placement as a Ring one, and can call Ring services by name.
governancecheck finds contract and placement defects before you run; docs generates the API catalog; diagnostics follow a shared contract.
operationsA browser admin panel that starts, stops and watches your apps; journal verify exits non-zero for cron; static files; a small ringserv.yaml.

How it is kept honest

625 gates, 22 suites

About seventy seconds for the whole thing. --full adds soak, benchmarks and a wide sweep over Ring's own ~470 samples.

A differential oracle

Programs are run against native ring.exe and compared byte for byte, so a compatibility regression cannot pass quietly.

Three platforms, every push

Linux, macOS and Windows build and run every gate in CI. Running them for the first time found five defects that one machine could not see.

Documentation that fails the build

The guides' own examples are extracted from the pages and executed. Prose that stops being true stops the build.

Honest limits

RingServ terminates no TLS — a TLS stack is the one dependency that cannot be vendored honestly, so put a proxy in front and say so. Intl and the YAML config are named subsets: they serve the common cases and refuse everything else by name, because a formatter that quietly gets your separators wrong is worse than one that admits it cannot. At 0.9 the API is stabilising, not frozen. What is still thin is listed in the repository, not hidden.
